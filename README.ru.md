# Placitum cookie

[English](README.md) · Русский

Инспектор куки Placitum. Выдаёт клиенту подписанную куку, снимает её, пишет её значение в живой
набор и рассказывает об этом соседям. Сам ничего не проверяет и никого не блокирует: по выданной
куке решают другие — локальный слой на узле, действия соседей, счётчик.

Проще всего это видно на рекламном трафике. Клиент приходит по ссылке с `utm_source=yandex-direct`;
инспектор кладёт ему подписанную куку с меткой источника, пишет значение в живой набор и ставит на
запись маркер `src:yandex-direct`. Кампания видна в журнале без единого похода в приложение, а узел
узнаёт клиента по набору — без шины и без инспектора.

```
модуль ──► waf.req.cookie ──► cookie ──► allow + Set-Cookie
                                 │
                                 ├── состояние куки: absent | present | invalid | expired
                                 ├── запись значения в живой набор
                                 └── просьбы соседям: маркер, очки
```

## Что нужно знать

- **Вердикт у него один — `allow`.** Очки на маршруте он двигает просьбой `score`, которую исполняет
  модуль. Собственные сбои — `verdict: error` с кодом `COOKIE_*`, а не тихий `allow`: `allow` прятал
  бы невыданную куку.
- **Работает на обеих фазах.** На фазе запроса кука ставится до апстрима, её видит и приложение. На
  фазе ответа известен код ответа, так что тому, кому апстрим ответил 404, куку можно не выдавать.
  Заголовки запроса на фазе ответа берутся из снимка запроса: `Cookie` присылает клиент, а не апстрим.
- **Подпись по умолчанию.** Куку, по которой установка принимает решения, без подписи набирают руками
  в консоли браузера. Подобранное значение — состояние `invalid`, а не «куки нет».
- **Маршрут обязан снимать заголовки.** Без них куку читать не из чего, и ответ — `error` с
  `COOKIE_HEADERS_UNAVAILABLE`. Считать это «куки нет» значило бы выдавать новую куку каждому на
  каждом запросе.

## Маршрут

```nginx
waf_inspector cookie subject=waf.req.cookie;

location / {
    waf_inspect request cookie wave=1 timeout=20ms;
    waf_capture request headers args;
    waf_cookie_defaults secure=on http_only=on same_site=Lax;
}
```

`args` нужен, если значение берётся из строки запроса (`value.from: $arg_utm_source`). Атрибуты
`secure`, `http_only` и `same_site` ставит `waf_cookie_defaults` маршрута, а не профиль: присланное с
провода модуль разбирает и выбрасывает. `Domain` модуль не ставит, кука остаётся host-only.

## Профиль

Профили приезжают от контроллера поколением; в образе лежит пустой `default`. Маршрут, который
называет профиль, которого у инспектора нет, получает `error` с `COOKIE_UNKNOWN_PROFILE`.

```yaml
mode: enforce

cookies:                 # объявления: что это за кука
  - name: waf_src
    path: /              # умолчание /
    max_age: 30d         # нет — кука сессии
    renew_after: 7d      # возраст, после которого состояние — expired
    sign: hmac           # hmac (умолчание) | none
    value:
      from: $arg_utm_source  # операнд: $arg_, $http_, $cookie_, $waf_request_args.<имя>
      default: direct        # метка, если источника нет
      random: 8              # случайный хвост в байтах; 0 — без него
      max_len: 64            # предел метки до сборки значения

conditions:              # именованные условия, те же, что у инспектора действий
  - name: from_ads
    any:
      - { value: $arg_utm_source, op: eq, text: yandex-direct }
      - { value: $arg_utm_source, op: eq, text: google }

rules:
  - name: first-touch    # имя живёт в журнале и аудите
    phase: request       # request | response; пусто — обе
    on: absent           # состояние куки на входе; пусто — любое
    if: from_ads         # условие профиля; unless — наоборот
    match:
      methods: [GET]
    issue: waf_src       # операция: выдать
    actions:
      - do: mark
        marker: "src:{tag}"   # подстановки: {tag}, {value}, {name}
      - list: ads_clients     # запись в живой набор
        write: cookie         # addr | net | net_all | asn | cookie
        ttl: 30d
        code: COOKIE_ADS

  - name: forged         # подпись не сошлась: куку подобрали
    on: invalid
    cookie: waf_src
    actions:
      - { do: score, value: 20, code: COOKIE_FORGED }

  - name: from-google    # метка предъявленной куки — одна из названных
    cookie: waf_src
    tags: [google]
    actions:
      - { do: mark, marker: "src:{tag}" }

  - name: logout
    match: { path_prefix: "/logout" }
    drop: waf_src        # операция: снять
    actions:
      - { list: ads_clients, write: cookie, op: remove }
```

### Состояния и операции

| `on` | Когда |
| --- | --- |
| `absent` | куки с таким именем клиент не прислал |
| `present` | кука есть, и подпись сошлась либо подписи не просили |
| `invalid` | кука есть, но подпись не сошлась, форма испорчена или время выдачи в будущем |
| `expired` | кука своя и целая, но старше `renew_after` |

Операций две, `issue` и `drop`, и правило делает одну из них. `on: absent` вместе с `issue` —
«первое касание»: кука достаётся только тому, у кого её нет. Правило без `on:` — «последнее
касание»: значение перезаписывается на каждом совпавшем запросе.

`tags: [google, yandex]` сужает правило по читаемой половине значения: оно срабатывает, когда метка
предъявленной куки — одна из названных. Метка есть только у существующей куки (`present`,
`expired`), поэтому с `on: absent` и `on: invalid` такое правило не грузится. Метку неподписанной
куки выбирает клиент, так что решать по меткам стоит только при `sign: hmac`.

Правила накопительные: срабатывают все совпавшие, действия складываются в порядке строк. Судьба самой
куки порядком не решается: **снятие сильнее выдачи**, и правило выхода не проиграет правилу
посадочной страницы, стоящему ниже.

### Значение и подпись

```
<метка>[~<случайное>][.<время>.<подпись>]
```

Метка — то, ради чего куку заводят: источник перехода, кампания, ветка теста. Она читается глазами и
уезжает в маркер записи, поэтому алфавит у неё узкий: всё, что не `[A-Za-z0-9_-]`, становится
подчёркиванием, а метка режется по `max_len`.

Ключ берётся из `WAF_COOKIE_SECRET_FILE` или `WAF_COOKIE_SECRET`, не короче 16 байт, один на все
копии. На куку он разводится её именем, поэтому подпись одной куки не подходит другой. Без ключа
профиль с `sign: hmac` отвечает `error` с `COOKIE_SECRET_MISSING`, а не выдаёт неподписанные куки
молча. Время выдачи живёт в подписанной половине, поэтому `renew_after` и состояние `expired` требуют
`sign: hmac`.

### Запись в наборы

Действие может быть записью, а не просьбой: `list` с `ttl` (и `write`, `op`, `code`), без `to` и `do`.
У `write` четыре вида, общих для всех отправителей, и один свой:

| `write` | Что уезжает в набор |
| --- | --- |
| `addr` | адрес клиента (умолчание) |
| `net` | эффективный анонс, самый узкий |
| `net_all` | все анонсы, накрывающие адрес, включая более широкие |
| `asn` | автономная система целиком |
| `cookie` | значение куки: выданной на этом запросе либо предъявленной клиентом |

Под `write: cookie` обычно и заводят набор на узле: `type=string`, почти всегда с `hash=md5`, чтобы
значения куки не лежали в разделяемой памяти открытым текстом. `op: remove` снимает запись. Анонсы и
системы даёт кодер гео (`WAF_COOKIE_GEO_ADDR`) в бюджете сообщения; молчащий кодер — `error` с
`COOKIE_GEO_UNAVAILABLE`.

## Коды причин

| Код | Что значит |
| --- | --- |
| `COOKIE_OK` | правила посчитаны |
| `COOKIE_IDLE` | не своя фаза (кадры WebSocket) |
| `COOKIE_PROFILE_OFF` | у профиля `mode: off` |
| `COOKIE_UNKNOWN_PROFILE` | маршрут называет профиль, которого у инспектора нет |
| `COOKIE_HEADERS_UNAVAILABLE` | маршрут не снимает заголовки запроса |
| `COOKIE_STORE_ERROR` | обменник не отдал объект, который лежал |
| `COOKIE_SECRET_MISSING` | кука подписывается, а ключа у процесса нет |
| `COOKIE_ISSUE_FAILED` | значение не собралось: длиннее предела, случайное не прочиталось |
| `COOKIE_GEO_UNAVAILABLE` | строка пишет сеть или систему, а кодер молчит |
| `COOKIE_QUEUE_LIMIT`, `COOKIE_DEADLINE_EXCEEDED` | перегрузка: очередь полна или бюджет вышел |

Что нужно рядом и все настройки — в [INSTALL.ru.md](INSTALL.ru.md).
