# Установка

[English](INSTALL.md) · Русский

Инспектор не слушает сеть: он подписчик очереди `waf.req.cookie` на шине. Адрес и сервис ему не
нужны, и добавление копии не трогает ни узел защиты, ни конфигурацию. Обычно его ставит
`placitum-core`.

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| NATS | да | очередь, аудит, журнал, поколение профилей |
| Ключ подписи | если куки подписываются | HMAC значения; без ключа профиль с `sign: hmac` отвечает `error` |
| Redis: обменник | да | заголовки запроса: без `Cookie` читать нечего |
| Redis: внутренний | при записи в наборы | зеркало наборов keeper; без него берётся обменник |
| `keeper` | при записи в наборы | ведёт состав живых наборов |
| `geo` | при `write: net`, `net_all`, `asn` | анонсы и состав системы |
| Контроллер | да | шлёт профили поколением |

## Ключ подписи

Не короче 16 байт и **один на все копии**: куку, выданную одной копией, должна читать другая.

```sh
openssl rand -hex 32 > secrets/cookie.hmac
```

Ключ отдают файлом (`WAF_COOKIE_SECRET_FILE`), а не переменной: окружение процесса видно соседям по
машине и уезжает в дампы. Если заданы оба, файл сильнее.

**Смена ключа делает все выданные куки поддельными.** Каждая кука, подписанная прежним ключом,
придёт как `invalid`, и если профиль начисляет за `invalid` очки, их разом получат все вернувшиеся
клиенты. Меняйте ключ вместе с профилем, а не в одиночку.

## Настройки

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `NATS_URL` | `nats://127.0.0.1:4222` | шина |
| `REDIS_URL` | из `inspector.conf` | обменник: заголовки и строка запроса |
| `REDIS_INTERNAL_URL` | из `inspector.conf` | внутренний Redis: зеркало наборов keeper |
| `WAF_COOKIE_SUBJECT` | `waf.req.cookie` | подписка; должна совпадать с `subject=` в объявлении инспектора |
| `WAF_COOKIE_NAME` | `cookie` | имя в реестре инспекторов и в кадре присутствия |
| `WAF_COOKIE_QUEUE` | имя | очередь шины |
| `WAF_COOKIE_PROFILES` | `./profiles`; в образе `/app/profiles` | профили; поколение контроллера их перекрывает |
| `WAF_COOKIE_DATA` | `<профили>.applied`; в образе `/var/lib/waf/cookie` | куда раскатка кладёт применённое поколение |
| `WAF_COOKIE_RELOAD_EVERY` | `1s` | как часто проверять каталог профилей |
| `WAF_COOKIE_SECRET_FILE` | пусто | файл с ключом подписи |
| `WAF_COOKIE_SECRET` | пусто | ключ переменной, если файла нет |
| `WAF_COOKIE_GEO_ADDR` | пусто | кодер гео (`host:port`) для записей сети и системы |
| `WAF_COOKIE_GEO_TIMEOUT`, `WAF_COOKIE_GEO_NEG_MAX` | `500ms`, `0` | ожидание кодера в бюджете сообщения и потолок отрицательного кэша |
| `WAF_COOKIE_CONF` | `inspector.conf` в рабочем каталоге, затем `/app/inspector.conf` | очередь и адреса Redis |
| `WAF_COOKIE_WORKERS` | число ядер | воркеры |
| `WAF_COOKIE_QUEUE_DEPTH`, `WAF_COOKIE_QUEUE_FULL`, `WAF_COOKIE_QUEUE_EXPAND` | `256`, `drop`, `off` | очередь и поведение при переполнении; то же через `inspector.conf` |
| `WAF_COOKIE_RESERVE_MS`, `WAF_COOKIE_MIN_BUDGET_MS` | `1`, `1` | запас на ответ и минимальный бюджет, ниже которого работа не начинается |
| `WAF_COOKIE_VERSIONS` | `2` | версии схемы сообщения, которые процесс принимает |
| `WAF_COOKIE_LOG` | `info` | стартовый уровень журнала; живьём его переставляет панель |
| `WAF_HEARTBEAT_EVERY` | `4s` | период кадра присутствия |
| `WAF_LOG_SHIP` | `on` | уезжает ли журнал процесса на шину; `off` оставляет только stdout |

## Docker Compose

```yaml
services:
  inspector-cookie:
    image: placitum/cookie
    environment:
      NATS_URL: nats://nats:4222
      REDIS_URL: redis://redis:6379
      REDIS_INTERNAL_URL: redis://redis-internal:6379
      WAF_COOKIE_SECRET_FILE: /run/secrets/waf_cookie_hmac
      WAF_COOKIE_GEO_ADDR: geo:50051
    secrets: [waf_cookie_hmac]
    depends_on: [nats, redis, redis-internal]

secrets:
  waf_cookie_hmac:
    file: ./secrets/cookie.hmac
```

## Проверка

В образе есть проба, она шлёт настоящее сообщение по шине; её же запускает `HEALTHCHECK`:

```sh
docker exec <контейнер> cookie-probe --quiet --timeout 1s
```

На маршруте с профилем выдачи в ответе должен прийти `Set-Cookie`:

```sh
curl -si 'http://<узел>/?utm_source=test' | grep -i '^set-cookie'
```

В журнале при здоровом старте: подключение к шине, загруженные профили, число воркеров. Если
`Set-Cookie` не приходит, первым делом смотрите режим вызова на маршруте: пассивный инспектор куки не
выдаёт.

## Грабли

- **Пассивный вызов ничего не выдаёт.** При `mode=passive` или `mode=vote` на вызове модуль секцию
  `cookies` из ответа не применяет. Выглядит как «включил, а куки нет».
- **Две фазы — две выдачи.** Вызов на обеих фазах маршрута отработает дважды; у правила выдачи тогда
  обязателен `phase:`.
- **Host-only.** `Domain` модуль не ставит: кука `shop.example.com` не видна на `www.example.com`.
- **Кеш.** `Set-Cookie` на кешируемом ответе — один клиент уносит куку другого. Статику из правил
  выдачи исключайте.
- **Длина.** Набор `type=string` держит запись до 256 байт, с `hash=md5` — 32; подписанное значение
  считается целиком.
